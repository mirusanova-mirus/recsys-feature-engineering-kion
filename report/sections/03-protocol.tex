Все более ранние события остаются прогревочной историей. Признаки для даты t используют строго \code{event.date < t}; окно w --- \texttt{[t\ensuremath{-}w,t)}. Внутри дня порядок неизвестен, поэтому события этого дня не используются даже для более поздних кандидатов. Модели учатся только на train. Search применяется для early stopping, выбора гиперпараметров и признаков. Confirm --- отдельная проверка выбранных решений. Test открывается в \code{experiment.py} после сохранения \code{selection.lock.json}; тестовые метрики не участвуют в выборе.

Протокол последовательный: после завершения дня его события становятся доступной историей следующего дня. Это относится и к валидации, и к тесту. Веса модели при этом фиксированы; переобучения на тестовых метках нет. Нельзя интерпретировать эту оценку как один прогноз всего тестового интервала из единственного снимка до его начала.

Каталог дня состоит только из объектов, хотя бы раз наблюдавшихся \textbf{до t у выбранных пользователей}. Положительные объекты вне каталога исключаются, доля покрытия приведена ниже. Уже виденные пользователем объекты исключаются из выдачи. Для каждого запроса добавляется 50 уникальных контролей: половина равномерно, половина с весами \code{past_item_count**0.75}, без возвращения. Положительные и отрицательные объекты перемешиваются. Seed генератора = 107, он зависит также от даты. Все модели получают одни и те же строки; контрольные SHA-256 каждого split записаны в \code{audit.json}.

Сегодняшние положительные объекты исключаются из контролей по определению разметки. \textbf{Будущие положительные взаимодействия не исключаются}: такое исключение дало бы кандидату информацию из будущего. Кандидаты и метки на тесте создаются офлайн до обучения; код выбора моделей не читает эти таблицы до фиксации решения.

Метрики условны на оценённых целях. Исключённым холодным объектам не приписывается нулевой score, поэтому это не end-to-end recall по всем исходным событиям. Весь eligible daily target set включается в кандидаты, и candidate recall внутри определённой задачи равен 1 по построению.
